React: Render, State, Effects và mental model hiện đại

Hudson
Jan 8
NOTES

React là thư viện để mô tả UI theo state. Component không “chỉnh DOM từng bước”; nó trả về mô tả giao diện cho state hiện tại, React reconcile và commit thay đổi cần thiết.

Component là phép biến đổi từ input sang UI

Props là input từ parent. Giữ render pure: cùng props/state nên tạo cùng output, không gọi API hoặc mutate dữ liệu trong render.

Render root hiện đại

ReactDOM.render thuộc API legacy. React vẫn có lịch sử, nhưng bài mới không cần cosplay năm 2020.

State là snapshot

State update được queue/batch; biến count trong một render là snapshot. Khi next state phụ thuộc previous state, dùng updater function.

Effects dùng để đồng bộ với hệ thống bên ngoài

Effect không phải chỗ mặc định cho mọi logic. Giá trị có thể tính từ props/state nên tính trong render; event-specific logic nên nằm trong event handler.

Keys và identity

Key giúp React giữ identity giữa các render. Tránh dùng array index khi item có thể reorder/insert/delete, nếu không state component có thể đi theo vị trí thay vì item—một màn hoán đổi danh tính khá khó debug.

State ownership

Đặt state ở component thấp nhất nhưng đủ chung cho những nơi cần nó. Không đưa mọi thứ lên global store. Context và Redux giải quyết coordination, không chữa thói quen không biết data thuộc về ai.

Mental model

  1. Render phải pure.
  2. State là snapshot.
  3. Event handler thay đổi state.
  4. Effect đồng bộ với external system.
  5. Cleanup effect khi subscription/request không còn cần.
  6. Identity nằm ở type, position và key.
